The orchestrator is ordinary code. It sets the order and runs the planner and the tailor at the same time.

AGENT 1

Evidence reader

Finds the lines that show what you have actually done.

AGENT 2

Direction mapper

Maps that evidence to 34 curated role families and names the gaps.

Run in parallel

Gap planner

Turns gaps into tasks sized to your hours.

CV tailor

Tightens your wording and adds no facts.

AGENT 5

Outreach writer

Drafts one email from a CV line and a line of company text.

Grounding layer, in code: every quote must appear in your CV, and a claim that fails is removed.

2:02 to 2:30. About 28 seconds. This is the slide to slow down on. SAY: "Behind the live mode is an orchestrator coordinating five specialist agents. An evidence reader finds what you have actually done. A direction mapper matches it to a curated list of 34 roles and names the gaps. Then a gap planner and a CV tailor run at the same time: one sizes tasks to your hours, the other tightens your wording. An outreach writer drafts the email. Each agent has one job, one output format, and its own checker. Today’s demo runs the offline engine; this agent mode is built and tested against a stand-in for the API." HOW THEY COORDINATE: the orchestrator is plain code, not a model. It runs the evidence reader, then passes its notes to the direction mapper. When the user chooses a direction, it runs the gap planner and the CV tailor in parallel and waits for both. The outreach writer runs when the user supplies a company and a pasted page. Each agent returns structured output against a fixed schema, and its validator checks the result before the next step uses it. HOW THIS IMPROVES RESULTS (by design, not measured): narrow roles are easier to check. The mapper can only choose from the curated role list and the role’s own requirements. The planner can only attach tasks to a stated gap. Errors are caught at each stage instead of flowing downstream. The parallel stage avoids waiting for two independent jobs one after the other. No benchmark is claimed. DETAIL: the default model is claude-opus-5-5, and each agent’s model can be overridden with an environment variable. Requests use structured outputs and the API’s server-side fallback. The user must tick a consent screen that shows exactly what will be sent before any text leaves the browser. STATUS, STATED PLAINLY: this mode has been exercised end to end in a browser against a local stand-in for the Anthropic API, which checked the request format, the consent gate and all five agents. It has not run against the live API yet, because that needs API credit.
